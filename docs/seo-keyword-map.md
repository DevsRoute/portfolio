# DevsRoute keyword-to-page map

This map assigns search intent to pages that already exist. It is not a search-volume report. Do not create extra pages for close variants of the same offer.

Positioning used on the site: a remote studio that helps startups and B2B founders build SaaS MVPs and AI-native products, with a clear scope and a defined end date.

## Primary pages

| Intent | Primary phrase | Page | Notes |
| --- | --- | --- | --- |
| Brand + offer | SaaS MVP development, AI product development | `/` | Homepage. Do not also target this as the only phrase on every service page. |
| Founder hiring a build team | SaaS MVP development for founders | `/founders` | Same offer as custom software, written for the buyer. Link to the service page. Do not copy the homepage FAQ word for word. |
| Add AI to a live product | AI features for SaaS teams | `/ai-features` | Narrower than the AI service page. |

| Web apps | Web application development | `/services/web-application-development` | React, Next.js, TypeScript, Node.js, and Python are named here as tools. |

## Phrases we will not give their own page

| Phrase | Why | Where it belongs |
| --- | --- | --- |
| MERN stack development company | The site does not sell MongoDB + Express as a distinct offer. A page for that phrase would be thin. | Mention React, Next.js, and Node.js on the web application page when the stack is relevant. |
| Python development company | Python is one backend tool, not a service line. | Web application and custom software pages. |
| SaaS development company / SaaS product development / custom SaaS development | Same intent as the homepage and the custom software page. Extra URLs would compete with each other. | `/`, `/founders`, `/services/custom-software-development` |
| Startup MVP development | Same intent as founders + custom software. | `/founders` |
| “Best” or “leading” AI company | Unsupported claim. | Do not use. |

## Rules

- One primary phrase per URL.
- Service FAQs stay specific to that service. The homepage answers cost, ownership, and how to start.
- Do not publish a price or a delivery time in weeks. The public answer is: scope and end date are agreed on the first call, with a demo every week.
- Do not add a blog post until there is an original article with a named author and a real date. Suggested later topics, not pages to generate in bulk:
  1. How to build a SaaS MVP
  2. What drives the cost of an AI-powered SaaS product
  3. When a startup should add AI
  4. How to choose a stack for a first version
  5. React and Node versus Python for a SaaS backend
